진행 상태: Windows 0.3.1 공개 알파. 인계 명세 전체 완료가 아님.

구현:
- PySide6 UI, 별도 worker, GPU 0의 로컬 llama.cpp CUDA 엔진
- 4개 모델 선택, 모델별 템플릿/샘플링/프롬프트, 작업별 모델 고정
- Qwen3.8 27B Q4 실험 기본값, Hy-MT2 7B 경량 모드 유지
- 원본 보존, 물리 쪽 선택, 체크포인트, 취소/재개, 부분 실패 재시도
- 본문 길이/강건한 처리 속도 기반 시간 범위, 초기 측정/지연/속도 변화 재측정 표시
- 한국어 재배치/영한 대조 PDF, 노트, 품질 JSON, 문단 검토 HTML
- 코드/링크/인용 보호, 숫자·부정 등 보조 검사, 관련 용어 사전
- 빈 줄·제목·글머리표 문단 복원, 인접 쪽 미완성 문장 연결과 원본 쪽 추적
- 로컬 CPU OCR, 스캔/혼합 PDF, 자동/끄기/강제 모드, 모델 SHA256 검증
- OCR 원문/신뢰도/쪽별 경고 기록, 기존 텍스트 중복 억제, 회전/잘림 좌표 대응
- 일반 문장 return 오분류 수정, 분수 기간/한국어 숫자 표기의 정규화
- 작업 원본 해시 확인, 기존 노트 보존, 앱 소유 엔진만 종료
- 루프백/임시 인증키, worker Python의 외부 DNS/연결 차단
- 다른 계열 모델의 증거 인용 기반 검수 경로 구현, 자동 교정 채택 없음

이번 비교:
- 모델당 합성 42개: 개발 진단 24개 + 별도 긴 문단 18개, 원시 프롬프트 v2
- Hy7B/Qwen3.8에 사전 적용 v3: 개발 24개 + 새 문단 12개
- 원시 모델 결과와 사전 적용 결과는 별도 보존. 전문가 정답/정확도 백분율 없음
- 에이전트의 선택적 비맹검 의미 검토, 사용자용 순서 섞은 비교 HTML 제공
- 검수 인위 오류 시험 Qwen30 8/10, Qwen3.8 10/10. 작은 시험만으로 자격 승인하지 않아 독립 검수 UI는 비활성
- 문맥 4096, 병렬 1, KV f16. 문맥/병렬/KV 전체 탐색은 미실시
- 큰 모델에도 시간 기준 오역, credible/confidence 혼용, 어색한 용어가 남음
- 자동 검사에 거짓 경고와 누락 모두 가능. 경고 0은 의미 정확도 보증 아님

남은 개발:
1. PDFMathTranslate/BabelDOC 기준선, 원문 조판 복원, 복잡한 표/수식/2단 IR
2. OCR 손글씨/수식/저해상도 개선, 복잡한 2단/표/부분 겹침의 읽기 순서 개선
3. 전문가 기준의 독립 held-out 60문단 이상과 검수 모델 자격 평가
4. 인명/약어/문서 문맥, 승인 번역 메모리, 검토 편집/되돌리기
5. 다운로드 UI, 대기열, 알림, 장문/휴면/드라이버 장애 검증

범위와 한계:
- 분야 선택은 기록용이며 검증된 분야별 모델 라우팅이 아님
- 합성 PDF 실행 성공을 실제 논문 의미 정확도로 해석하지 않음
- 전원 관리 API 구현, 실제 sleep/wake 시험 미실시
- 시간 범위는 휴리스틱이며 완료 시각 보증/통계적 신뢰구간이 아님. OCR/검수/저장은 별도 단계
- 로컬 신규 추론/차단 감사 훅 시험, NIC 비활성화 시험 미실시
- native 엔진을 OS 방화벽으로 격리한 것은 아님
- 원문/사용자 Vault/기존 작업은 변경하지 않음. 개발 출력은 test_vault만 사용
