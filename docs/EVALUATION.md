# 개발 단계 모델 비교

## OCR 복원과 문서 용어 (0.5.3a1)

206개 단위 검사를 통과했습니다. 실제 로컬 CPU OCR로 의도적으로 누락시킨 한 줄을 잘라 다시 읽고,
worker 번역·출력 배치 검사·원문 면 픽셀 보존·추가 OCR/모델 호출 없는 재개까지 검사했습니다.
이 경로 검사의 번역은 테스트 대역이며, 임의 스캔의 OCR 정답률이나 실제 번역 의미 품질 점수가 아닙니다.
빈 이미지·긴 선·큰 단색 도형의 재인식 제외, 좌표 역변환, 취소, 낮은 점수/범위 이탈 거부,
코드·열·도식·미확인 Table 캡션의 오병합 방지를 검사했습니다.
선정 용어와 원문 약어 정의가 멀리 떨어진 문단에서도 같은 초벌/교정 힌트에 쓰이고,
중의적/미등록 약어나 검증되지 않은 번역에서 용어를 만들어내지 않는지 검사했습니다.

실제 스캔 3쪽에서 단어별 출현 수를 모두 유지한 채 번역 대상은 36개에서 31개로 줄었습니다.
이미 인식된 영역에서 새 OCR 줄은 추가되지 않았습니다. 측정 문서와 원문 기록은 공개하지 않습니다.
이는 소수 페이지의 요청 단위 비교이며 전체 번역 시간이나 의미 정확도의 개선 비율은 아닙니다.
진행 중인 GPU 작업을 유지해 실제 GPU의 1/2문단 비교는 수행하지 않았고 기본값 1을 유지합니다.

## 저장·응답 재사용·실험 동시 처리 (0.5.2a1)

196개 단위 검사를 통과했습니다. 기존 JSON 가져오기, 다른 설정의 기록 분리, 삭제한 실패 기록이
낡은 JSON에서 되살아나지 않는 것, 실제 별도 프로세스의 비정상 종료 후 마지막 커밋 보존을 검사했습니다.
같은 합성 PDF에서 순차/2문단 동시 처리의 최종 번역·상태·배치와 원문 면 픽셀이 일치했습니다.
각 방식은 모델 호출 13회, 동일 입력 재사용 3건이었으며 재개 때 추가 생성 없이 완료됐습니다.
이는 CPU 테스트 대역의 경로 검사입니다. 실제 GPU의 속도나 의미 품질 보증으로 해석하지 않습니다.

로컬 작업 기록 사본 7,350개에서 24회 변경을 저장하는 측정은 전체 JSON 재작성 10.05초,
새 저장 방식은 초기 가져오기 0.53초 + 변경 커밋 0.22초 + 최종 호환 사본 0.58초, 합계 1.34초였습니다.
최종 데이터는 같았습니다. 다른 작업이 실행 중인 장비에서 한 번 측정한 저장 작업 비교이며,
프로그램 전체 번역 속도가 같은 비율로 빨라진다는 뜻은 아닙니다. 실제 문서와 측정 원시 기록은 공개하지 않습니다.
기본값은 순차 처리이고 기존 보완/교정 범위는 유지합니다. 보완 대상 자동 선별은 품질 비교 전 적용하지 않습니다.

소스와 새 Windows 실행 파일 모두에서 실제 Hy-MT2를 CPU로 실행해 native/스캔 합성 2쪽을 검사했습니다.
순차/2문단 동시 각각 번역 실패 0, OCR 1쪽, 전 출력 2쪽 배치 검사 통과, 동일 입력 재사용 2건,
추가 생성 없는 재개를 확인했습니다. 이 작은 입력의 최종 번역 문자열도 두 방식에서 같았습니다.
원본 해시·선택 쪽·분석기·OCR 설정이 같은 완성 분석도 재사용하며, 내용 손상과 설정 변경·중간 취소 시의 무효화를 검사합니다.
GPU 적재는 0으로 설정하고 CPU 4스레드를 사용했습니다. 실제 GPU 처리량·장문 의미 품질 비교는 별도로 남아 있습니다.

## 배치·도식·재검사 (0.5.1a1)

회전/정방향 6개 노드 도식, 질문/응답 격자 분리, 비교표 열 분리, 좁은 영역의 전체 항목 보충면,
행 표지와 짧은 목록, 어두운 배경을 합성 회귀 입력으로 검사합니다. 글자 계획과 PDF 추출 텍스트,
글자 겹침과 페이지 이탈을 출력의 모든 쪽에서 검사합니다. 이는 OCR 정답이나 번역 의미의 인증이 아닙니다.
심한 누락, 총 회기 수의 주당 빈도 오역, 미완성 자리표시자, ADHD 용어를 잘못 옮긴 후보는 재번역합니다.
잘못된 인용이나 수량으로 거부된 교정 후보는 거부 사유를 포함해 최대 3번 재검사하며 후보를 모두 보존합니다.
본문은 최소 9pt, 도식 내부 문구는 최소 8pt입니다. 상자에 맞춘 문구 교정도 원문 개념을 보존해야 합니다.
원문 자체가 가림/훼손되어 읽히지 않는 부분을 채우는 기능이나 전문가 독립 정답 평가는 포함하지 않습니다.

0.5.1에서는 176개 단위 검사와 배치·교정·남은 시간의 CPU 통합 검사를 통과했습니다.
실제 Windows 실행 파일에서도 합성 4쪽의 OCR→표 6개 셀 분리→회전 도식 6개 문구 인식→
GPU 번역·문구 교정→쪽 대응→PDF 저장을 검사했습니다. 출력 4쪽 모두 배치 검사를 통과했고,
원본 SHA256·대조본 원문 면 픽셀·번역 범위 보존과 원시 응답을 변경하지 않는 캐시 재개를 확인했습니다.
별도 데이터 루트에서 실행 파일 UI 시작도 확인했습니다. 이 결과는 해당 합성 입력의 실행 경로 검증이며,
새 문서의 의미 정확도나 복잡한 표 전체의 자동 복원을 보장하지 않습니다.

## 원문 위치 대응 (0.5.0a1)

합성 입력에서 원문의 같은 열·높이로 문단 배치, native/스캔 표의 셀 구분,
일부 캡션 숫자 열 무테 표, 최소 글꼴과 보충면의 텍스트 보존을 검사합니다.
회전·잘림 원문 면은 출력 왼쪽과 픽셀을 비교합니다. 쪽별 대응은 번역을 다시 쓰지 않고
기존 문장 범위만 선택합니다. 경계 문장 하나는 양쪽에 표시할 수 있으며,
대응 추정과 미확정은 보고서에 남깁니다. 기계 대응은 의미 정확도 보증이 아닙니다.
전체 표·복잡한 병합 셀·도식 내부의 OCR·2단 조판의 일반적인 복원은 미완성입니다.
0.5.0에서는 153개 단위 검사와 CPU 합성 통합 검사를 통과했습니다.
실제 Windows 실행 파일에서도 별도 데이터 루트의 합성 3쪽으로 OCR→6개 표 셀 분리→
Hy-MT2 번역→짧은 셀 4개 Qwen 교정→쪽 대응→PDF 저장을 검사했습니다.
원문 면 픽셀·원본 SHA256·기존 번역의 정확한 문자열 범위·원시 응답 변경 없는 재개를 확인했습니다.
이는 작은 합성 입력의 실행 경로 검증이며 실제 문서 전체 품질 평가가 아닙니다.

## 문맥·교정·영어 OCR 변경 (0.4.0a1)

영어 문장과 기존 한국어 번역을 대조하는 교정 경로를 추가했습니다. Hy-MT2 7B와
Qwen3.8 27B를 문맥 8192, 병렬 1로 순차 실행했습니다. 모델을 동시에 적재하지 않습니다.
별도 합성 진단 10개와 의도적으로 잘못 만든 번역/유지 대조 사례를 사용했습니다.
교정 모델은 부정 누락, 상관관계의 인과관계화, 재량의 의무화와 일부 직역을 바로잡았으나
경제 문맥의 depression을 임상적 우울증으로 그대로 두기도 했습니다.
이에 문맥에 맞는 용어 힌트와 오류 감지를 추가했습니다. 이 작은 개발 시험을
독립 평가나 정확도 백분율로 제시하지 않습니다.

교정은 원문·초안의 실제 인용 근거와 숫자/보호 문자열 검사를 통과해야 자동 채택합니다.
원문 자체의 OCR 누락, 미묘한 의미 변화 및 자연스러움을 완전히 판정할 수는 없습니다.
독립 검수 모델 자격 승인과 사람의 승인은 별도이며, 자동 교정으로 승인되지 않습니다.
실제 Windows 실행 파일에서 합성 4문단의 Hy-MT2 초벌→Qwen 교정→내보내기 흐름을 검사했습니다.
초벌 캐시를 유지한 채 인위적으로 넣은 부정 누락을 다시 교정하는 경로도 통과했습니다.
이 통합 검사는 일부러 만든 작은 입력이며 문서 전체의 의미 정확도 시험과 구분합니다.
0.4.1 시점의 124개 단위 검사를 통과했습니다. 큰 OCR 머리말을 제외한 쪽 사이 연결,
인용 복원, 분수의 정확한 값·부호와 잘못된 비율 거부도 합성 사례로 검사합니다.

영어 스캔에는 MuPDF의 Tesseract OCR과 공식 tessdata_best 영어 데이터를 우선 사용합니다.
검사한 인쇄 영어 샘플에서는 기존 감지기가 놓친 줄을 더 많이 복원했습니다.
전체 문서 OCR 정답 데이터나 일반화된 정확도 수치는 없습니다. 이 경로의 행 신뢰도는
노출되지 않아 '점수 없음'으로 기록하며 원문 대조가 필요합니다. RapidOCR는 보조 경로입니다.
OCR의 투명 글꼴 상자가 앞뒤 줄에 겹쳐 읽기 순서가 달라지는 사례를 확인해
짧게 겹친 줄은 논리적 순서를 유지하도록 수정했습니다. 원본 좌표·인식 문자는 보존합니다.

무료 API는 키가 없는 상태에서 HTTP 테스트 대역으로 모델 가격, 0원 라우팅,
유료 대체 금지와 오류 시 로컬 결과 유지를 검사했습니다. 실제 외부 API의
번역 품질·가용성·무료 할당량 소진 동작은 검증하지 않았습니다.

## OCR 경로 검증 (0.3.0a1)

소스 실행과 Windows 실행 파일에서 로컬 CPU OCR과 실제 GPU 번역을 연결해 합성 스캔/혼합 PDF 3쪽을 검사했습니다.
스캔 3쪽 인식, 한 문단의 쪽 사이 연결, 기존 PDF 텍스트 중복 억제,
번역 실패 0문단, 원본 복사본 SHA256 일치를 확인했습니다.
단위 검사에는 회전/잘림 좌표, 빈 쪽, 낮은 신뢰도, 강제/끄기 모드,
큰 페이지 렌더 한도 및 취소 확인을 포함합니다.
이 검사는 실행 경로의 검증이며 실제 논문 OCR 정확도나 의미 정확도 평가가 아닙니다.

이 자료는 에이전트가 작성한 합성 문단과 에이전트의 선택적 비맹검 검토입니다.
전문가 정답, 정확도 백분율, 최종 품질 승인은 없습니다. GPU는 RTX 4090 24GB입니다.

## 원시 모델 비교

모델마다 같은 42개 입력(개발 진단 24개 + 별도 긴 문단 18개)을 사용했습니다.
문맥 4096, 병렬 1, KV f16, GPU 적재를 사용했습니다. 모델별 프롬프트/샘플링은 달랐습니다.
아래 시간은 적재 후 최초 42개 요청의 총시간으로 적재·PDF 내보내기는 제외합니다.
GPU 메모리는 1초 간격으로 관측한 장치 전체 사용량의 최댓값으로, 화면과 다른 앱도 포함합니다.

| 모델 | 요청 총시간 | GPU 전체 사용량 최댓값 |
| --- | ---: | ---: |
| Hy-MT2 7B Q6 | 57.73초 | 9.15GiB |
| Qwen3 30B-A3B Instruct Q4 | 23.77초 | 20.64GiB |
| TranslateGemma 27B Q4 | 117.58초 | 20.73GiB |
| Qwen3.8 27B Q4 | 105.58초 | 19.51GiB |

Qwen30B-A3B는 빨랐지만 친족·재료·전문용어 오류가 있어 기본 품질 모델로 선정하지 않았습니다.
원시 Qwen3.8도 엽서→우표, 땋은 머리→머리카락 한 가닥, 준정부호 용어 오류가 있었습니다.
자동 검사 경고가 없어도 의미가 틀린 사례가 있었습니다. 장문·다른 GPU의 속도는 추정하지 않습니다.

## 사전 적용 앱 프로필

관련 용어 사전을 적용한 프롬프트 v3으로 Hy7B/Qwen3.8을 비교했습니다.
개발 진단 24개와 새로 작성한 12문단을 사용했으므로 위 원시 모델 비교와 구분해야 합니다.
Qwen3.8은 일부 문단에서 친족 불확정성, 배정/은폐/맹검, 결측/무작위 배정 구분을 더 명확히 보존했습니다.
사전은 두 모델의 엽서·땋은 머리·준정부호 번역을 개선했습니다.
그러나 시간 기준 변경, 기록 매체 추가, credible/confidence 용어 혼용이 남았습니다.
최종 합성 PDF에서도 aunt를 고모로 특정하고 원문 인명을 음역했습니다.

따라서 Qwen3.8은 **고품질 실험 모드**로만 표시합니다. 더 큰 모델이 항상 더 정확하다는 뜻은 아닙니다.
첫 설치는 하드웨어 부담이 낮은 Hy7B를 사용하며 Qwen3.8은 선택 설치합니다.
검수 모델의 작은 인위 오류 시험만으로 자격을 승인하지 않아 추가 검수는 기본 비활성입니다.

## 범위

- 저장소에는 합성 입력 두 세트만 포함하며, 로컬 경로를 포함한 원시 실행 기록은 제외했습니다.
- 공개 코드의 테스트와 CI 결과는 각각 확인할 수 있습니다. 개발판에서는 18개 단위 검사가 통과했습니다.
